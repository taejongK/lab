# MVP — 개발 로그

> 중단 후 재개할 때는 이 파일과 `docs/notes/01.architecture.md`를 읽으면 바로 이어서 작업할 수 있다.

---

## 목표

**무엇을 만드는가**: 도트 스타일 2D 맵에서 플레이어 1명과 LLM NPC 2명 이상이 움직이고 대화하는 최소 버전.

**왜 만드는가**: 작은 로컬 모델(Qwen 3.5 0.8B, uzu)로 NPC가 상호작용만으로 스스로 이동·대화할 수 있는지 확인하려고.

**판정 질문**: LLM 판단만으로 NPC가 스스로 목적지를 골라 이동하는가? 서버 로그에서 `NPC → LLM 출력 → 이동` 흐름이 반복되는 것을 확인하면 MVP 성공.

**범위 원칙**: 이 질문 확인에 필요 없는 것은 최소한으로만 만든다 (대화는 말풍선 한 줄, 기억은 최근 사건 몇 개, 에셋은 받을 수 있으면 입히고 아니면 색 사각형).

**완료 기준**:
- 맵 1개, NPC 2명 이상, 플레이어 1명이 한 화면에서 움직인다.
- 플레이어 입력 없이 두어도 NPC가 LLM 판단으로 이동·대화를 이어간다.
- 플레이어가 NPC에게 한 말이 그 NPC의 다음 행동에 반영되는 것을 로그로 확인할 수 있다.

## 개발 계획

- [x] 1. uzu 스모크 테스트: 모델 다운로드, 한 번 호출, 지연 시간 측정, JSON 행동 출력 형식 지키는지 확인
- [x] 2. 서버 뼈대: FastAPI + `/ws` + 정적 파일 서빙, 하드코딩 맵, 월드 틱 루프
- [x] 3. 프론트 뼈대: Canvas 2D로 맵·엔티티 그리기(도트), 방향키 → `move` 전송
- [x] 4. NPC 이동: 장소 목록, BFS 경로, 랜덤 목적지로 먼저 동작 확인
- [x] 5. NPC 판단: 랜덤을 LLM 호출로 교체, 파싱 실패 → `wait`
- [x] 6. 대화: `say` 말풍선, 플레이어 `say` 입력창, 최근 사건 기억 → 다음 판단에 반영
- [ ] 7. 도트 에셋 입히기 (Kenney Tiny Town 후보)

## 메모

- 1단계 결과 (M-series Mac, Qwen 3.5 0.8B mirai-m:4): 자유 출력 0.33~0.40s, JsonSchema 제약 0.58~0.62s, 각 5회 모두 유효 JSON.
- uzu API 주의: `ReasoningEffort.Disabled`는 enum 값(호출 X), system 메시지에만 붙일 수 있음. `session.reply`는 기록을 누적하므로 독립 판단마다 `reset()`.
- 관찰: "빵집 빵이 신선하다"는 사건을 줘도 bakery 대신 well/plaza를 고름 — 기억이 행동에 반영되는지는 6단계에서 다시 본다.
- 5단계 측정 (2분): Mina 31호출 → 28이동, 목적지 4종, 무효 3 / Tom 29호출 → 27이동, 3종, 무효 2. 무효는 대부분 현재 장소(`well`)를 그대로 말한 경우. 지연 0.26~0.36s.
- 6단계 A/B (Mina@well, 20회씩, 기억에 플레이어 말 1개만): 없음 → plaza 20 / "go to the bakery" → bakery 16, plaza 4 / "go home" → home 19, plaza 1. 기억 없을 땐 거의 결정적(같은 답).
- 6단계 2분 통합 (플레이어가 우물 근처에서 10초마다 말함): NPC별 30~31호출 → 25이동, 목적지 4종, 무효 17~19% (전부 현재 장소 `well`을 다시 고른 경우 — 대화에 well이 자주 나와서). 플레이어 말을 들은 직후 다음 목적지가 요청과 일치 10/18. NPC끼리도 서로의 말을 듣고 목적지를 바꿈 (예: tom "We will visit the bakery" → mina bakery).
- `say` 필드 추가 후 무효율이 7~10% → 17~19%로 올랐지만 통과 기준(<30%) 안.
- 주의: 선택지가 3개뿐이라 "서로 다른 목적지 ≥3"은 쉽게 채워진다. 이 결과는 "LLM이 형식에 맞게 목적지를 골라 계속 움직인다"까지만 보여주고, 그 선택이 상황을 반영하는지는 6단계에서 본다.
