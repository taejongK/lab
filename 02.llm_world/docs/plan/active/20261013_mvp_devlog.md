# MVP — 개발 로그

> 중단 후 재개할 때는 이 파일과 `docs/notes/01.architecture.md`를 읽으면 바로 이어서 작업할 수 있다.

---

## 목표

**무엇을 만드는가**: 도트 스타일 2D 맵에서 플레이어 1명과 LLM NPC 2명 이상이 움직이고 대화하는 최소 버전.

**왜 만드는가**: 작은 로컬 모델(Qwen 3.5 0.8B, uzu)로 NPC가 상호작용만으로 스스로 이동·대화할 수 있는지 확인하려고.

**판정 질문**: LLM 판단만으로 NPC가 스스로 목적지를 골라 이동하는가? 서버 로그에서 `NPC → LLM 출력 → 이동` 흐름이 반복되는 것을 확인하면 MVP 성공.

**범위 원칙**: 이 질문 확인에 필요 없는 것은 최소한으로만 만든다 (대화는 말풍선 한 줄, 기억은 최근 사건 몇 개, 에셋은 받을 수 있으면 입히고 아니면 색 사각형).

**완료 기준**:
- 맵 1개, NPC 2명 이상, 플레이어 1명이 한 화면에서 움직인다.
- 플레이어 입력 없이 두어도 NPC가 LLM 판단으로 이동·대화를 이어간다.
- 플레이어가 NPC에게 한 말이 그 NPC의 다음 행동에 반영되는 것을 로그로 확인할 수 있다.

## 개발 계획

- [ ] 1. uzu 스모크 테스트: 모델 다운로드, 한 번 호출, 지연 시간 측정, JSON 행동 출력 형식 지키는지 확인
- [ ] 2. 서버 뼈대: FastAPI + `/ws` + 정적 파일 서빙, 하드코딩 맵, 월드 틱 루프
- [ ] 3. 프론트 뼈대: Canvas 2D로 맵·엔티티 그리기(도트), 방향키 → `move` 전송
- [ ] 4. NPC 이동: 장소 목록, BFS 경로, 랜덤 목적지로 먼저 동작 확인
- [ ] 5. NPC 판단: 랜덤을 LLM 호출로 교체, 파싱 실패 → `wait`
- [ ] 6. 대화: `say` 말풍선, 플레이어 `say` 입력창, 최근 사건 기억 → 다음 판단에 반영
- [ ] 7. 도트 에셋 입히기 (Kenney Tiny Town 후보)

## 결정 사항

| 결정 | 이유 | 날짜 |
| ---- | ---- | ---- |
| 렌더링은 Canvas 2D 순수 JS, 도트 스타일 | 가장 간단, 빌드 없음. 필요해지면 Phaser로 | 2026-10-13 |
| 서버 FastAPI, 통신 WebSocket 하나 | FastAPI가 WebSocket 기본 지원, 실시간 상태 전송에 맞음 | 2026-10-13 |
| 서버가 월드 상태의 유일한 원본 | NPC 판단과 플레이어 이동을 한 곳에서 일관되게 처리 | 2026-10-13 |
| NPC 목적지는 좌표가 아니라 장소 이름 | 0.8B 모델은 좌표 계산보다 이름 선택이 쉬움 | 2026-10-13 |
| 프론트는 FastAPI가 정적 서빙 | 서버 하나만 띄우면 됨, CORS 불필요 | 2026-10-13 |
