# 01. 아키텍처 (MVP 초안)

> 상태: 초안 (2026-10-13). 구현하면서 바뀌면 이 문서를 고치고 devlog 변경 이력에 남긴다.

## 전체 구조

```
브라우저 (frontend/)                       서버 (server/, FastAPI)
┌──────────────────────┐   WebSocket /ws   ┌───────────────────────────────┐
│ Canvas 2D 렌더링      │ ◀──── state ───── │ 월드 틱 루프 (이동·충돌)        │
│ 키 입력 → input 전송  │ ───── input ────▶ │ NPC 판단 루프 ── LLM(uzu) 호출 │
└──────────────────────┘                    └───────────────────────────────┘
```

- 서버가 월드 상태의 유일한 원본이다. 프론트는 받은 상태를 그리고 입력을 보내기만 한다.
- 프론트 정적 파일(`frontend/`)은 FastAPI가 `/`에 그대로 서빙한다. 서버 하나만 띄우면 되고 CORS도 필요 없다.

## 월드

- 그리드 맵: 20×15 타일, 타일 16px, 화면에서는 ×3으로 확대한다 (초안 값).
- 타일 종류: 바닥 / 벽(통과 불가). 맵은 서버 코드 안의 문자열 배열로 시작한다.
- **장소(landmark)**: 맵 위에 이름 붙은 지점 몇 개 (예: `광장`, `우물`, `빵집`, `집`). NPC는 좌표 대신 장소 이름으로 목적지를 고른다. 작은 모델은 좌표 계산보다 이름 고르기를 훨씬 잘하기 때문이다.

## 서버 루프

두 루프를 분리한다.

1. **월드 틱** (예: 200ms마다): 이동 중인 엔티티를 경로를 따라 한 칸 옮기고, 모든 클라이언트에 `state`를 보낸다. LLM을 기다리지 않는다.
2. **NPC 판단**: NPC가 할 일이 없을 때(목적지 도착, 말하기 끝, 대기 시간 끝)만 LLM을 부른다. 모델 인스턴스가 하나이므로 호출은 한 번에 하나씩(큐 또는 lock) 처리한다.

경로 탐색은 그리드 BFS로 충분하다 (맵이 작다).

## NPC 판단

LLM 입력(관찰):
- 자기 이름·성격 한 줄, 현재 위치(가장 가까운 장소 이름)
- 근처(예: 3칸 이내) 엔티티 이름
- 최근 사건 N개 (들은 말, 한 말, 도착한 장소) — 이게 "상호작용이 이동에 영향"을 주는 통로다
- 고를 수 있는 장소 목록

LLM 출력(행동) — JSON 한 줄. 선택지는 **현재 장소를 뺀 장소들**만 준다 (`wait` 없음, 도착 후 `IDLE_TICKS` 대기가 그 역할):

```json
{"target": "well", "say": "I need water for the bread."}
```

- `say`(선택)는 말풍선으로 `BUBBLE_TICKS` 동안 보이고, `NEARBY` 안의 다른 NPC 기억에 `"<이름> said: ..."`로 들어간다.

- 서버는 응답 텍스트에서 선택지 장소 이름을 찾기만 한다 (펜스·키 이름 오류 허용). 없으면 **무효**로 로그를 남기고 대기 후 재시도. 서버가 대신 고르지 않는다 (랜덤 대체 금지).
- 이렇게 바꾼 이유: 처음 설계(`move`/`wait` + 전체 장소)에서는 0.8B가 관찰에 보인 현재 장소를 따라 말해 `wait`에 고착됨. devlog 2026-10-13 참고.
- `say`는 말풍선으로 몇 초 표시되고, 대상이 NPC면 그 NPC의 최근 사건에 들어가 다음 판단을 유도한다.

## 프로토콜

WebSocket `/ws`, 메시지는 JSON. `type` 필드로 구분.

서버 → 클라이언트:

```json
{"type": "init", "you": "player", "map": ["####...", "#...#"], "tile": 16, "landmarks": [{"name": "우물", "x": 5, "y": 4}]}
{"type": "state", "tick": 123, "entities": [{"id": "npc1", "name": "미나", "kind": "npc", "x": 4, "y": 7, "dir": "left"}],
 "bubbles": [{"id": "npc1", "text": "안녕!"}]}
```

클라이언트 → 서버:

```json
{"type": "move", "dx": 1, "dy": 0}
{"type": "say", "text": "우물로 가 봐"}
```

- 플레이어의 `say`는 근처 NPC들의 최근 사건에 들어간다. 텍스트는 서버에서 80자로 자른다.
- 좌표는 타일 단위 정수. 부드러운 이동 보간은 프론트가 그리기에서만 한다.

## 미확인 / 열린 질문

- (확인됨) uzu Python API는 async: `Engine.create` → `engine.model(id)` → `engine.download` → `engine.chat` → `session.reply(msgs, cfg)`. 세션은 기록을 누적하므로 독립 판단마다 `session.reset()`.
- (확인됨) 지연: 호출당 약 0.3~0.6s. NPC 몇 명은 순차 호출로 충분.
- (확인됨) **uzu 0.6.3에서 `Grammar`(JsonSchema·Regex)는 설정해도 무시된다** — 불가능한 enum(`zzz_only`)을 줘도 평소 출력이 나옴. 형식은 프롬프트의 `Format:` 줄로만 유도되고, 서버 쪽 관대한 파싱이 필요하다.
- 프롬프트는 영어로 시작 (작은 모델 기본값). 장소 이름도 영어(`plaza`, `well`, `bakery`, `home`).
