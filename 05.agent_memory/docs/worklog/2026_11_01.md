### 대표 메모리 방법론 동작 다이어그램
- 질문: 카테고리별 대표 방법론이 큰 그림에서 어떻게 동작하나? (LLM·데이터 = 노드, 입출력 = 엣지)
- 결과 요약: 6개 카테고리 대표 방법론 33개를 Mermaid 다이어그램으로 그려 설계 비교 보고서 3.8절에 넣고, 보고서를 HTML로 전환
- 방법:
  - 노드 4종 구분: LLM / 데이터·저장소 / 입출력 / 처리 단계 (LLM 아님 또는 원문에서 세부 미확인)
  - 엣지 라벨 = 오가는 데이터, 점선 = 트리거·보상·선택적 흐름
  - 근거는 노트 01과 동일한 수집 원문, 다이어그램마다 원문 링크
  - 헤드리스 Chrome 렌더링 확인: 다이어그램 33개·표 6개, 문법 오류 0
  - 보고서 원본 .md는 삭제, 기존 링크(README·index·노트·worklog)는 .html로 교체
- 보고서: [에이전트 메모리 설계 비교](../report/2026_10_27_agent-memory-design-comparison.html)
- 남은 문제:
  - 논문은 초록 수준이라 내부 구조는 큰 그림만
  - Mermaid CDN 의존 (오프라인에서 그림 안 보임), GitHub에서는 HTML 미렌더링

### CS 챗봇 메모리 구조
- 질문: 규정 문서와 과거 대응 기록을 불러오는 CS 챗봇에는 어떤 메모리 구조가 제일 맞나?
- 결과 요약:
  - 규정은 메모리가 아니라 조항·버전 단위 원문 저장소로 두고, 과거 기록은 사례 카드로 추출
  - 카드마다 근거 조항 버전을 달고 사용 전 현재 버전과 대조하는 것이 핵심
  - OS식 계층·RL 관리·완전한 시간 지식 그래프는 제외 (짧은 대화, 감사 어려움, 버전 태그로 충분)
- 방법:
  - 6개 카테고리를 CS 요구사항(조항 정확성, 사례 재사용, 규정 개정, 감사 가능성)에 대입
  - 구성요소마다 근거 원문 재확인, 인용 문장은 원문 grep으로 대조
  - 재확인 중 오류 1건 정정: 유지·수정·삭제 통합의 근거를 Mem0(현재 ADD-only) → CrewAI Memory로 교체
  - 헤드리스 Chrome으로 렌더링·링크 확인
- 보고서: [CS 챗봇 메모리 구조](../report/2026_11_01_cs-chatbot-memory-architecture.html)
- 남은 문제:
  - 실험 아닌 설계 제안, CS 대상 벤치마크 없음
  - 사례 카드가 정답률을 실제로 올리는지, 색인 방식이 버티는 규정 규모 미측정
