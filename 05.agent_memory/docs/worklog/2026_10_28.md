- 결과 요약: 논문 48편 초록 원문, 구축 사례 34건 본문 원문 확보
- 방법:
  - 논문: arXiv API로 ID 조회 → 제목 일치 확인 → 초록 원문 저장 (아키텍처 28, 학습 9, 서베이 6, 벤치마크 5)
  - 2023-10 이전 기초 논문 10편 포함, "(pre-window)" 표시
  - 사례: 요약형 웹 조회 대신 스크립트로 원문 다운로드 (마크다운은 그대로, HTML은 trafilatura 본문 추출)
  - 사례 구성: 상용 어시스턴트 8, 코딩 에이전트 7, 오픈소스 14, 엔지니어링 글 5
- 남은 문제:
  - 논문 코드 저장소 링크 미검증, 학회 정보는 대부분 arXiv 코멘트 기준
  - 2026-06 이후 메모리 벤치마크 약 25편은 영향력 판단 불가로 제외
  - 소비자용 Microsoft Copilot 메모리, Zep 블로그, Semantic Kernel 미수집

### 에이전트 메모리 설계 비교
- 질문: 메모리 설계에서 내려야 할 결정은 무엇이고, 연구와 실서비스는 각각 어떤 선택을 하나?
- 결과 요약:
  - 연구는 저장 구조(그래프·계층·latent)와 RL 기반 관리에, 실서비스는 마크다운 파일 + 작은 색인 상시 로딩에 집중
  - 실서비스의 난제는 검색보다 "저장된 기억이 아직 맞는가" (읽기 시 검증 / 무효화 / 백그라운드 정리로 갈림)
  - 갱신 연산(append-only vs LLM CRUD vs RL 학습)은 합의 없음
  - LoCoMo·LongMemEval 수치는 벤더 자체 측정이라 상호 비교 불가
- 방법:
  - 서베이 공통 축을 합쳐 6개 결정 축 설정 (저장 대상·형태·쓰기·읽기·갱신/망각·범위)
  - 사례 원문에서 시스템별 사실·인용 추출, 핵심 인용 9개는 원문 grep으로 재확인
  - 보고서 상대 링크 77개 실제 파일 존재 확인
- 보고서: [에이전트 메모리 설계 비교](../report/2026_10_27_agent-memory-design-comparison.md)
- 남은 문제: 논문은 초록만 확인, 상용 어시스턴트 내부 구조는 비공개
- 작업자: taejongK

### 메모리 아키텍처 패턴 정리
- 질문: 최근 주목받는 메모리 방식의 대표 방법론은 어떤 아키텍처로 구성되나?
- 결과 요약: 6개 카테고리로 정리 — 파일 기반 계층 / OS형 계층 / 추출·통합 레이어 / 시간 인지 KG / 경험·절차 / RL 학습 관리
- 방법:
  - 카테고리별 공통 구조 다이어그램 + 대표 방법론 3~6개의 구성요소·쓰기/읽기 흐름
  - 초록·문서에 없는 내부 구조는 쓰지 않고 "본문 미확인"으로 표시
- 문서: [01. 메모리 아키텍처 패턴](../notes/01.memory-architecture-patterns.md)
- 남은 문제: 파라미터·latent 메모리(Titans 등)는 실서비스 사례가 없어 제외
- 작업자: taejongK
