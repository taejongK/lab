## 2026_11_05

### 캐릭터 엔진의 방향과 첫 버전 범위 정의
- 질문: 창작자가 게임을 만들고 NPC가 살아 있는 것처럼 반응하는 엔진을 어떻게 구성할까?
- 결과 요약: AI가 게임 마스터와 NPC를 맡는 2D TRPG 엔진으로 정의. 첫 완료 기준은 왕 독살 후 NPC가 기억하고 새 왕이 탄생하는 장면
- 방법:
  - System One 전제와 기존 실험 결론을 버리고 사용자 인터뷰로 요구사항 재정리
  - 실패 기준을 "캐릭터가 앞선 일을 잊고 엉뚱하게 반응"으로 확정
  - 독립 검토자가 설계 문서를 읽고 공백 7건 지적 → 5건 작성자 판단으로 반영, 2건(계승 방식, 발각 시 처벌)은 사용자 결정
  - 사용자 결정: 계승은 정해진 순서, NPC는 체포까지 가능하고 플레이어 사망 없음
- 남은 문제: 구현 전이라 실제 Claude API에서 일관성과 행위 제안 품질 미측정
- 보고서: [AI TRPG 캐릭터 엔진 설계](../plan/active/2026_11_05_character-engine-design.md)
- 작업자: taejongK (Claude 작성)

### 왕 독살 장면을 돌리는 엔진 첫 버전 구현
- 질문: 설계한 구조로 왕 독살 → NPC 기억 → 새 왕 탄생 장면이 동작하나?
- 결과 요약: 가짜 AI로는 전 과정 동작. 실제 Claude로는 미검증 (API 키 없음). 핵심 질문인 판단·일관성 품질은 아직 답하지 못함
- 방법:
  - 세계 규칙, 사건 흐름, Claude 호출, 브라우저 화면을 나눠 구현. 시나리오는 파일 하나로 분리
  - 자동 플레이로 발각·미발각 두 분기와 잘못된 AI 응답 거부 확인 (가짜 AI, 통과)
  - Chrome에서 직접 조작: 이동, 약병 줍기, AI 추가 행위 선택, 왕 사망·계승 공표, NPC 대화 확인
  - 독립 코드 검토 1회: 지적 HIGH 7건 전부 수정, MEDIUM·LOW도 수정 후 재발 방지 검사 추가
    - 주요 수정: 다른 사람의 소지품이 NPC에게 보이던 문제, AI의 공표로 지식 규칙이 뚫리던 문제, 목격 후보 계산 시점, 문턱에서 한 행위가 숨겨지던 문제
- 남은 문제:
  - `src/ai.py`는 실제 호출 0회. 응답 스키마가 서버에서 받아들여지는지도 미확인
  - 독 타기 제안 5판 중 5판, 일관성, 비용, 지연 미측정 (`playtest.py --real`로 측정 예정)
  - 체포 후 풀려나는 방법 없음. 저장·불러오기, 메모리 검색은 미구현 (메모리는 통째로 전달)
