## 2026_11_05

### 캐릭터 엔진의 방향과 첫 버전 범위 정의
- 질문: 창작자가 게임을 만들고 NPC가 살아 있는 것처럼 반응하는 엔진을 어떻게 구성할까?
- 결과 요약: AI가 게임 마스터와 NPC를 맡는 2D TRPG 엔진으로 정의. 첫 완료 기준은 왕 독살 후 NPC가 기억하고 새 왕이 탄생하는 장면
- 방법:
  - System One 전제와 기존 실험 결론을 버리고 사용자 인터뷰로 요구사항 재정리
  - 실패 기준을 "캐릭터가 앞선 일을 잊고 엉뚱하게 반응"으로 확정
  - 독립 검토자가 설계 문서를 읽고 공백 7건 지적 → 5건 작성자 판단으로 반영, 2건(계승 방식, 발각 시 처벌)은 사용자 결정
  - 사용자 결정: 계승은 정해진 순서, NPC는 체포까지 가능하고 플레이어 사망 없음
- 남은 문제: 구현 전이라 실제 Claude API에서 일관성과 행위 제안 품질 미측정
- 보고서: [AI TRPG 캐릭터 엔진 설계](../plan/active/2026_11_05_character-engine-design.md)
- 작업자: taejongK (Claude 작성)

### 왕 독살 장면을 돌리는 엔진 첫 버전 구현
- 질문: 설계한 구조로 왕 독살 → NPC 기억 → 새 왕 탄생 장면이 동작하나?
- 결과 요약: 가짜 AI로는 전 과정 동작. 실제 Claude로는 미검증 (API 키 없음). 핵심 질문인 판단·일관성 품질은 아직 답하지 못함
- 방법:
  - 세계 규칙, 사건 흐름, Claude 호출, 브라우저 화면을 나눠 구현. 시나리오는 파일 하나로 분리
  - 자동 플레이로 발각·미발각 두 분기와 잘못된 AI 응답 거부 확인 (가짜 AI, 통과)
  - Chrome에서 직접 조작: 이동, 약병 줍기, AI 추가 행위 선택, 왕 사망·계승 공표, NPC 대화 확인
  - 독립 코드 검토 1회: 지적 HIGH 7건 전부 수정, MEDIUM·LOW도 수정 후 재발 방지 검사 추가
    - 주요 수정: 다른 사람의 소지품이 NPC에게 보이던 문제, AI의 공표로 지식 규칙이 뚫리던 문제, 목격 후보 계산 시점, 문턱에서 한 행위가 숨겨지던 문제
- 남은 문제:
  - `src/ai.py`는 실제 호출 0회. 응답 스키마가 서버에서 받아들여지는지도 미확인
  - 독 타기 제안 5판 중 5판, 일관성, 비용, 지연 미측정 (`playtest.py --real`로 측정 예정)
  - 체포 후 풀려나는 방법 없음. 저장·불러오기, 메모리 검색은 미구현 (메모리는 통째로 전달)
- 작업자: taejongK (Claude 작성)

### 도트 그래픽과 전용 인터랙션 화면으로 UI 교체
- 질문: 캐릭터를 도트 2D로 보여 주고, 인터랙션을 별도 화면으로 전환할 수 있나? 나중의 창작자 도트 에디터로 이어지나?
- 결과 요약: 필드와 인터랙션 화면 모두 교체 완료, 가짜 AI로 동작 확인. 도트는 시나리오 데이터로 저장해 에디터 저장 형식으로 재사용 가능. 에디터는 미구현
- 방법:
  - 캐릭터·물건·타일을 16×16 문자열과 팔레트로 작성. 게임 시작 때 형식 검사
  - 90년대 말 휴대용 RPG 느낌은 참고하되 특정 게임의 그림·화면은 쓰지 않고 새로 제작
  - 자동 플레이 통과: 도트 형식, 대화 중인 NPC가 자리를 떠나지 않는 규칙 검사 추가
  - Chrome에서 가짜 AI로 조작: 약병 줍기, AI 추가 행위, 결과 표시, 왕 사망 소식, 쓰러진 모습, 기억 창, 대화. 콘솔 오류 0건
  - 일부 키 입력은 스크립트로 넣음
- 남은 문제:
  - 실제 Claude 미검증. 응답 대기 화면의 체감도 미확인
  - 감옥 안 화면과 창살 너머 대화는 브라우저 미확인 (자동 플레이로 대화 가능 여부만 확인)
  - 마지막에 수정한 경비대장 투구는 화면 재확인 안 함 (형식 검사만 통과)
  - 마우스 조작, 좁은 화면 미시험. UI 변경분 독립 검토 안 함
  - 한글 도트 폰트(갈무리)를 CDN에서 불러옴. 오프라인이면 시스템 폰트로 대체
- 작업자: taejongK (Claude 작성)

### 창작자 페이지, 홈 화면, OpenRouter 연결
- 질문: 창작자가 페이지에서 게임을 만들어 바로 플레이할 수 있나? LLM을 OpenRouter로 돌릴 수 있나?
- 결과 요약: 작은 새 게임을 페이지에서 만들어 실제 모델로 플레이 성공. OpenRouter 응답 형식 5종 모두 통과. 홈에서 게임 만들기와 카드형 게임 선택 가능
- 방법:
  - 세계관, 캐릭터, 공간, 규칙 4개 탭과 도트 에디터 구성. 편집 상태와 저장 파일을 같은 시나리오 형식으로 유지
  - 미완성도 저장, 플레이는 시나리오 검사 통과 후에만 허용
  - Chrome에서 새 게임 `폭풍의 등대` 제작 후 플레이: 등대지기가 창작자가 넣은 기억대로 열쇠 요구를 거절. 콘솔 오류 0건
  - `왕의 술잔`을 불러와 복사 저장 → 캐릭터, 방, 행위, 역할, 도트가 원본과 일치
  - 경로 탈출 이름 저장 거부(400), 없는 파일 요청 거부(404) 확인
  - OpenRouter 오류 처리는 가짜 서버로 자동 검사 추가. 잘못된 키와 키 없음은 실제 실행으로 시작 전 차단 확인
  - 홈 카드: 정상, 미완성, 손상 파일 세 경우를 임시 파일로 확인 후 삭제
- 남은 문제:
  - `왕의 술잔`을 빈 화면부터 페이지로 다시 만드는 전체 과정 미확인
  - 플레이어 변경, 물건·타일 그리기, 감옥 칸·NPC 자리 지정 기능을 직접 눌러 보지 않음
  - 일부 입력은 스크립트로 처리. 좁은 화면 미확인. 독립 코드 검토 안 함
  - 게임을 고를 때마다 처음부터 시작. 저장·이어하기 없음

### 실제 모델로 왕 독살 장면 측정
- 질문: 가짜 AI가 아닌 실제 모델에서도 왕 독살 뒤 새 왕이 탄생하나?
- 결과 요약: 아니오. DeepSeek 5판 중 독 타기 제안 5판, 왕 사망 0판, 새 왕 0판. 첫 버전 완료 기준이 실제 모델에서는 미충족
- 방법:
  - `playtest.py --real --runs 5`, 모델 `deepseek/deepseek-v4.1-flash`, 발각 강제 3판과 미발각 강제 2판
  - 술잔 상태 변경 2판. 그 2판에서도 왕 생존
  - 총비용 약 0.154 USD. 판별 지연 중앙값 4~7초, 최대 53초
- 남은 문제:
  - 왕이 죽지 않은 원인 미확인 (저녁 식사 판정 원문을 남기지 않음)
  - 미발각 강제 판에서 체포 1회, 원인 미확인
  - 5판째는 크레딧 부족 오류로 뒷부분 오염. 다른 모델 미측정
- 보고서: [실제 LLM 왕 독살 첫 측정](../report/2026_11_05_openrouter-real-run.md)
