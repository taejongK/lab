### System One 모델로 게임을 할 때 공간 정보를 어떻게 넣나
- 질문: Jev 같은 System One 모델로 게임을 플레이한 사례들은 state·질문·행동을 어떻게 구성했고, 공간 정보는 어떻게 넣었나?
- 결과 요약: 모든 사례가 공간 계산은 코드가 하고 결과를 텍스트로 넘김. 학습 없이는 전체 격자로 행동을 바로 고르지 못하고, 이미지 입력은 게임 데이터로 학습한 모델에서만 동작
- 방법:
  - 게임 사례 10건(Doom·Snake·T-Rex·Minecraft 등) 수집, 그중 5개 저장소는 state 생성 코드를 직접 읽음
  - 공간 표현 8가지로 분류 (화면 bbox, 전체 격자, 국소 창, 자기중심 각도·거리, 방향별 여유 공간, 선택지 설명에 결과 적기 등)
  - NanoJev 비교 실험 확인: 전체 지도로 바로 행동 선택 시 Jev 포함 미로 0/3, 국소 5×5 + 코드 플래너는 3/3, ASCII에 좌표 추가 시 완주율 +30~55%p
  - 이미지 사례: PlayJev(0.8B, 화면 1장, 탐색 알고리즘 정답으로 학습, 10종 평균 0.57), Valen(타일 이미지 + {상하좌우})
- 남은 문제: 표현만 바꾼 비교는 NanoJev 하나(seed 1개, 지도 40장). 이미지 vs 텍스트 비교 사례 없음
- 보고서: [System One 게임 플레이 사례](../report/2026_10_25_system-one-game-play.md), [공간 정보를 state에 넣는 방법](../report/2026_10_25_spatial-state-encoding.md)

### ASCII 2D 맵 + 오브젝트 설명으로 NPC 이동을 정할 수 있나
- 질문: ASCII 맵에 현재 위치와 오브젝트 설명을 넣고 System One 모델이 이동 방향을 고르게 하는 로직이 가능한가?
- 결과 요약: 학습 없는 모델에 방향을 직접 고르게 하면 무작위 수준. 목표 오브젝트 고르기는 가능. 모델은 목표 선택, 코드는 BFS 경로로 나누면 가능
- 방법:
  - 로컬 Laya 421M(학습 없음, Apple M2), 무작위 9×9 맵 60개, 오브젝트 5개(설명 포함)
  - 한 걸음 정답률: 무작위 56%, ASCII만 68%, 방향별 사실 추가 67%, 짧은 사실 55%
  - 목표 도달(최단 거리 2배 안, 20판): 무작위 1, ASCII 4, 사실 추가 5
  - 방향별 확률 0.29~0.36으로 거의 균등. 입력 잘림 0/785
  - 자극 → 목표 오브젝트 선택: 19/30 (무작위 20%). 오답은 주로 목마름 → 모닥불, 추움 → 침대
  - 응답 시간 중앙값 158ms
  - 결과를 바탕으로 틱 루프·데이터 형식·설계 규칙·단계별 계획과 동작 데모를 담은 HTML 설계 문서 작성
- 남은 문제: Jev 미측정. 표본 작음. 목표 선택 63%는 낮음(설명 문구 개선·미세조정 필요). 움직이는 목표·다수 NPC 미검증
- 보고서: [ASCII 맵 NPC 엔진 (HTML)](../report/2026_10_25_ascii-map-npc-logic.html)
