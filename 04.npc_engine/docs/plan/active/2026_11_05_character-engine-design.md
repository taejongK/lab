# AI TRPG 캐릭터 엔진 — 설계

- 작성일: 2026-11-05
- 상태: 승인됨 (2026-11-05)
- 표기: 별도 표시가 없으면 사용자가 정한 내용. `[제안]`은 작성자(Claude)가 정한 기본값이며, 만드는 사람이 더 나은 방법을 찾으면 바꿔도 된다.
- 기존 조사·실험(System One, ASCII 맵)은 전제로 삼지 않는다.

## 1. 무엇을, 왜

창작자가 세계와 시나리오를 준비하면 AI가 게임 마스터와 다른 플레이어들을 맡아 진행하는 TRPG를, 2D 게임 형태로 만드는 엔진이다.

기존 게임의 NPC는 정해진 줄거리에서 벗어나면 막히거나 준비된 대사를 반복한다. 이 엔진에서는 플레이어가 줄거리를 벗어나도 세계가 그 결과를 받아 이야기를 이어 가고, NPC가 살아 있는 것처럼 반응한다.

예: 왕을 구하는 줄거리에서 플레이어가 왕을 죽이면 게임은 막히지 않고 "새 왕이 탄생했다"로 이어진다.

## 2. 목표

### 최종 목표
1. 캐릭터의 성격과 특징을 설정하면, 자극에 따라 자유롭게 행동한다.
2. 행동에 움직임이 필요하면 움직임도 자유롭게 한다.
3. 캐릭터마다 개별 메모리가 있다.
4. 게임 엔진처럼 창작자가 자기 게임을 만들고, 유저는 그 안에서 자유롭게 플레이한다.

### 첫 버전의 완료 기준
플레이어가 왕을 독살하면 NPC들이 기억하고 새 왕이 탄생하는 장면까지 동작한다.

1. 플레이어가 방향키로 성 안을 돌아다니다 술잔 앞에서 인터랙션을 시도한다.
2. 행위 목록에 AI가 추가한 "술에 독 타기"가 뜨고, 플레이어가 고른다.
3. 게임 마스터가 상황을 보고 성공 여부와 발각 여부를 판정한다.
4. 왕이 죽으면 "왕 사망"이 확정된 사실로 저장된다.
5. NPC들이 각자 아는 만큼 다르게 반응한다. 목격자는 플레이어를 의심하고, 모르는 NPC는 의문사로 받아들인다.
6. 계승 순서에 따라 다음 순번인 인물이 바로 새 왕이 되고, 모두에게 공표된다.
7. 시간이 지난 뒤 플레이어가 NPC에게 말을 걸어도 이 일과 어긋나지 않게 답한다.

"술에 독 타기"는 대본으로 넣지 않는다. 시나리오의 기본 행위에 없어야 하고, AI가 상황을 보고 제안해야 한다.

통과 조건 `[제안]`:
- 7단계가 매 판 그대로 나올 필요는 없다. 독살 실패와 발각은 정상 결과이며, 그 경우에도 세계가 막히지 않고 이어져야 한다.
- 플레이어가 독을 들고 술잔 앞에 있을 때 독 타기 행위는 반드시 제안되어야 한다. 5판 중 5판을 기준으로 한다.
- 시나리오는 사실을 적을 수 있지만("이 독은 마시면 죽는다"), 행위 자체나 진행 순서를 적으면 대본으로 본다.
- 발각·미발각 분기와 왕의 음주 시점은 디버그 옵션으로 강제할 수 있다. 일반 플레이에서는 쓰지 않는다.

### 비목표 (첫 버전)
- 멀티플레이. 1인용이다.
- 맵 여러 개, 대규모 NPC, 저장·불러오기 `[제안]`
- 왕위를 둘러싼 정치 싸움. 계승은 정해진 순서대로 일어나고, NPC의 불만은 대화와 태도로만 드러난다.
- 플레이어 사망과 게임 오버. NPC는 플레이어를 체포해 옥에 가둘 수 있지만 죽이지 못한다. 갇힌 뒤에도 대화는 할 수 있다.
- 엄격한 목표 모드의 구현. 설정 자리만 시나리오 형식에 남겨 둔다. `[제안]`

### 안티목표 — 동작해도 실패인 경우
캐릭터가 앞에서 일어난 일을 잊고 엉뚱하게 반응하는 것. 사용자가 꼽은 실패 장면이며, 대사의 화려함보다 일관성을 우선한다.

## 3. 역할

| 역할 | 하는 일 |
|---|---|
| 창작자 | 세계, 캐릭터, 큰 줄거리, 기본 행위를 정한다. 줄거리를 얼마나 엄격하게 따를지 정한다 |
| 플레이어 | 자기 캐릭터만 조작한다: 방향키, 인터랙션, 채팅 또는 선택지 |
| AI 게임 마스터 | 상황에 맞는 행위를 추가하고, 결과를 판정하고, 세계에 반영한다 |
| AI 캐릭터 | 성격과 자기 메모리를 바탕으로 말하고 행동한다 |

## 4. 플레이어 조작

- 방향키로 자기 캐릭터를 움직인다.
- 대상 앞에서 인터랙션을 시도하면 가능한 행위 목록이 뜬다.
  - 창작자가 정한 기본 행위 + 상황에 따라 AI가 추가한 행위.
- "대화"를 고르면 채팅이나 선택지로 이어진다.
- 행위를 고르면 AI 게임 마스터가 결과를 판정한다.

## 5. 엔진 구조

### 게임의 흐름
```
플레이어·NPC의 행위, 또는 게임 마스터·일정이 일으킨 사건
  → 게임 마스터가 결과 판정
  → 결과를 검증해 세계 상태에 반영
  → 코드가 누가 이 일을 알게 되는지 계산
  → 해당 NPC의 메모리에 기록
  → NPC가 반응, 필요하면 다음 행위로 이어짐
```

### 세계 상태 — 진실의 원본 `[제안]`
확정된 사실은 AI의 기억에 맡기지 않고 코드가 데이터로 저장한다.

- 캐릭터(생사, 위치, 소지품), 오브젝트 상태(술잔에 독 있음), 사건 기록.
- 역할과 인물을 분리한다. "왕"은 역할이고 누가 맡는지는 바뀔 수 있다.
- AI는 세계 상태를 직접 고치지 못한다. 정해진 형식으로 변경을 제안하고 코드가 검증해 적용한다.
- 변경 종류는 일반적인 몇 가지로 한정한다: 사실 추가·변경, 캐릭터 사망, 플레이어 구금, 위치 이동, 소지품 이동, 역할 이전. AI가 새로운 행위를 만들어도 결과는 이 안에서 표현한다.
- 이미 죽은 캐릭터의 행동, 존재하지 않는 대상, 플레이어 사망 같은 변경은 거부한다.

### 게임 마스터 `[제안]`
- 모든 것을 안다. 행위 추가와 결과 판정, 사건 진행을 맡는다. 역할 이전은 시나리오 규칙대로 코드가 적용한다.
- 판정할 때 시나리오의 규칙과 줄거리, 현재 세계 상태를 받는다.
- 판정은 주사위 없이 AI의 판단으로 한다. 왕이 독살되거나 들키는 결과가 상황에 맞게 나오면 된다.
- 결과가 나중에 나타나는 행위는 사건을 나눈다. 독 타기는 "술잔에 독 있음"만 남기고, 왕이 마실 때 별도 사건으로 죽음을 판정한다. 독을 탄 장면과 왕이 쓰러진 장면의 목격자가 달라야 하기 때문이다.
- 게임 마스터는 플레이어 행위 없이도 사건을 일으킬 수 있다. 시나리오의 일정(예: 저녁 식사)도 사건이 된다. 왕이 끝내 마시지 않는 경우도 정상 결과이지만, 일정이 있어 보통은 장면이 멈추지 않는다.

### AI 캐릭터 `[제안]`
- 자기 시트, 자기 메모리, 지금 보이는 상황만 받는다. 전체 세계 상태는 받지 않는다.
- 들키지 않은 독살은 재상에게 그냥 왕의 의문사다. 이 정보 차이가 필수 동작이다.
- 말하기와 행동 모두 같은 방식으로 판단한다. 행동은 플레이어와 같은 행위 목록에서 고른다.

### 메모리 `[제안]`
캐릭터별로 둘로 나눈다.

- 직접 겪은 사건과 전해 들은 말: AI가 추측으로 만들어 넣지 않는다.
  - 목격: 코드가 위치로 알아챌 수 있는 후보를 계산하고, 게임 마스터가 그 후보 안에서 실제로 알아챈 캐릭터와 이해한 정도를 판정한다. 후보 밖의 캐릭터는 고를 수 없고, 알아채지 못한 후보에게는 기록하지 않는다.
  - 전해 들은 말: "공주가 플레이어에게서 '재상이 범인'이라고 들음"처럼 누가 말했는지와 함께 저장한다. 세계 사실로 취급하지 않는다.
- 느낌과 해석: AI가 쓰는 부분. "플레이어가 수상하다" 같은 내용. 사실과 구분해 저장한다.

매 응답 전에 관련 기억과 그 캐릭터가 아는 공개 사실을 넣는다.

일관성 확인의 기준은 세계 상태가 아니라 그 캐릭터가 아는 것이다.
- 모르는 캐릭터가 "병으로 돌아가신 것 같다"고 말하는 것은 정상이다.
- 캐릭터는 목적에 따라 거짓말할 수 있고, 잘못 믿을 수 있다. 범인이 시치미를 떼는 것도 정상이다.
- 근거 없는 의심은 허용한다. 모르는 캐릭터가 범인을 사실처럼 단정하는 것은 실패다.
- 실패는 자기가 겪은 일을 잊은 듯 말하거나, 알 수 없는 사실을 아는 경우다. 내보내기 전에 걸러 다시 생성한다.

### 움직임 `[제안]`
- 행위에 위치 조건이 있으면 코드가 경로를 찾아 이동시킨다. AI는 어디로 갈지만 정한다.
- 타일 이동은 실시간, AI 판단은 사건이 생길 때 비동기 실행한다. 사건이 없을 때의 NPC는 시나리오의 일과를 코드로 따른다.
- AI가 응답하는 동안 게임은 멈추지 않고, 플레이어에게는 생각 중임을 보여 준다.
- 플레이어가 지켜보지 않아도 NPC는 각자 움직인다.

### 시나리오 파일 `[제안]`
창작자가 쓰는 유일한 입력이다. 사람이 읽고 쓰기 쉬운 형식(YAML 또는 JSON)으로 다음을 담는다.

- 맵과 오브젝트
- 캐릭터 시트: 성격, 특징, 목적, 관계, 처음 아는 것
- 역할과 그 이전 규칙 (왕이 죽으면 계승 순서). 순서대로 코드가 적용하며, 앞 순번이 죽었으면 다음 순번으로 넘어간다.
- 기본 행위 목록
- 큰 줄거리와 엄격도 (첫 버전은 오픈 월드만)

## 6. 첫 시나리오: 성 `[제안]`

- 작은 성 맵 하나. 알현실, 복도, 주방 정도.
- NPC 4~5명: 왕, 공주, 재상, 경비 등. 계승을 두고 입장이 다르게 설정한다.
- 왕의 술잔, 독을 구할 곳.
- 엔진 코드에 이 시나리오 전용 처리를 넣지 않는다. 왕, 독, 계승은 모두 시나리오 파일과 AI 판단으로 나와야 한다. 다른 시나리오로 바꿔 끼울 수 있어야 엔진이다.

## 7. 제약과 기술 선택

- 브라우저에서 돌아가는 탑다운 2D 타일 게임. `[제안, 사용자 승인]`
- AI는 Claude API. 플레이 중 호출 비용이 든다. `[제안, 사용자 승인]`
- 코드는 저장소의 `04.npc_engine` 폴더에 둔다. 다른 실험 폴더에서 import하지 않는다. `[제안, 사용자 승인]`
- API 키를 브라우저에 노출하지 않는다. 호출은 작은 서버를 거친다. `[제안]`
- 비용과 지연의 상한은 처음에 두지 않고 측정한다. 대신 한 판의 API 호출 수 상한을 설정으로 두어 비용이 무한정 늘지 않게 한다. `[제안]`
- 이 저장소 규칙상 테스트와 추상화는 최소로 하고, 실행해서 확인한다.

## 7-1. 화면과 도트 (2026-11-05 사용자 요청)

- 캐릭터는 도트 기반 2D 그래픽으로 그린다.
- 인터랙션을 시도하면 별도의 인터랙션 화면으로 전환한다. 90년대 휴대용 RPG의 느낌을 목표로 하되, 특정 게임의 캐릭터·그림·화면 구성을 베끼지 않고 이 엔진 고유의 그림으로 만든다.
- 나중에 창작자 페이지에서 도트 캐릭터를 만들 수 있어야 한다. 그래서 도트는 코드나 이미지 파일이 아니라 시나리오 데이터로 둔다. `[제안]`

도트 데이터 형식 (`scenarios/*.sprites.json`, 에디터의 저장 형식이 된다):

```
{ "characters": { "<id>": { "palette": {"k": "#241c2e", ...},
                            "frames": {"down": [16칸 문자열 16줄], "up": [...], "side": [...]} } },
  "objects":    { "<id>": { "palette": {...}, "frames": {"idle": [...]} } },
  "tiles":      { "<맵 문자>": { "palette": {...}, "frames": {"idle": [...]} } } }
```

- `.`은 투명. 그 외 글자는 팔레트의 색. 형식이 틀리면 게임이 시작하지 않는다.
- 캐릭터는 3장(정면·뒷면·왼쪽 옆면)만 그리면 된다. 걷기는 좌우 반전으로 만들고, 인터랙션 화면의 큰 그림은 같은 도트를 확대해 쓴다. 창작자의 작업량을 줄이기 위해서다.

## 7-2. 창작자 페이지와 LLM (2026-11-05 사용자 요청)

- `/create`에서 세계관, 캐릭터, 공간, 규칙 4개 탭으로 게임을 만든다. 편집 상태와 저장 파일은 같은 시나리오 형식이다.
- 탭에 넣는 항목은 사용자 요청 3개(세계관·캐릭터·공간)에 규칙(기본 행위, 역할과 계승, 정해진 사건)을 더한 것이다. `[제안]`
- 초안은 문제가 있어도 저장한다. 플레이만 막고 고칠 내용을 문장으로 보여 준다. `[제안]`
- LLM은 OpenRouter로 호출한다. 키와 모델은 `.env`에서 읽는다. 응답 형식은 `response_format`의 `json_schema`로 강제하고, 지원 제공사로만 보내도록 `require_parameters`를 켠다 ([Structured Outputs](https://openrouter.ai/docs/features/structured-outputs), [Chat Completions](https://openrouter.ai/docs/api-reference/chat-completion)).

## 8. 검증 `[제안]`

- 완료 기준 7단계를 실제 API로 직접 플레이한다. 발각된 경우와 들키지 않은 경우를 모두 확인한다.
- 사건 후 NPC마다 "왕은 어떻게 됐나", "누가 범인인가"를 묻고 그 NPC가 아는 것과 대조한다. 5절의 일관성 기준으로 어긋난 응답 수를 기록한다.
- 응답 지연과 플레이 1판의 API 비용을 기록한다.
