# 02. 아키텍처와 학습 방법

**이 문서의 절반은 "모른다"이다.** 논문도 기술 리포트도 가중치도 없다.
아래는 블로그 포스트 + 외부 추론 + 기자 취재를 합친 것.

## 알려진 것 (TypeSafe 주장)

### Parallel sampler (비-autoregressive)

토큰을 순차 생성하지 않는다. **모든 출력을 단일 쿼리에서 한 번에** 낸다.
한 요청 안의 여러 질문도 동시에 평가된다.

→ 그래서 70~500ms. autoregressive 디코딩 루프 자체가 없음.

관찰자들이 붙인 이름: "constrained or diffusion-like decision model".
GPT 계열의 대체재가 아니라 다른 물건이라는 뜻.

### 타입 안전성이 "구조적으로" 보장됨

가능한 출력과 구조가 **사전에 전부 정의**되므로 타입 에러가 원리상 불가능.
TypeSafe 본인들 각주가 솔직하다:

> "Our number is not empirical. Schema matching is guaranteed,
>  thus we can confidently add 0% into the plots."

즉 "0% 환각"은 측정값이 아니라 정의상 참인 명제. **스키마 환각만** 없앤 것이고
의미적으로 틀린 판단은 여전히 가능하다.

### RLCD (Reinforcement Learning for Calibrated Decisions)

| | 최적화 대상 |
|---|---|
| RLHF | 사람이 선호하는 텍스트 |
| RLVR | 검증 가능한 정답 |
| **RLCD** | **구조화된 결정 위의 epistemically honest 확률** |

목표 성질: 확률이 실제 불확실성을 의미 있게 반영해야 한다.
= 확률 0.8짜리 예측들의 묶음은 실제로 80% 정도 맞아야 한다 (calibration).

## 모르는 것 (= 연구 포인트)

- **파라미터 수, 백본 구조, 학습 데이터** — 전부 비공개
- **calibration curve 미공개**. calibration을 핵심 세일즈 포인트로 내세우면서
  정작 reliability diagram을 안 냈다. 이게 제일 이상한 지점.
- **RLCD의 실제 알고리즘**. 이름만 있고 수식이 없다.
- 아키텍처 논문 없음, 공개 리더보드 점수 없음, (출시 시점 기준) OpenRouter 미등재.

## 회의론: "이거 그냥 constrained decoding 아닌가?"

Sean Goedecke의 지적이 가장 날카롭다:

1. **기술적 해자가 얕을 수 있다** — 기존 LLM에 구조화된 템플릿을 prefill 하고
   제약된 단일 토큰만 생성시키면 비슷한 성능이 나온다. 전용 하드웨어도 필요 없을 수 있음.
2. **지능 천장이 있다** — test-time reasoning을 못 쓰므로 프론티어 모델을 못 따라간다.
3. **"환각 면역"은 과장** — 제약된 선택지 안에서 잘못 고르는 것도 여전히 에러다.

반론 쪽 정리: logit bias/constrained decoding은 **토큰 레벨 제약**일 뿐이고,
RLCD는 **확률 자체를 calibration 타깃으로 학습**했다는 점에서 다르다 — 는 것이
TypeSafe의 차별점 주장. 다만 이걸 확인할 근거가 아직 없다.

그럼에도 커뮤니티 톤은 대체로 긍정적이었다. HN 1,800+ points, ~480 comments.
"결정에 특화된 빠르고 싼 모델"이라는 아이디어 자체는 오래 기다린 것이라는 반응.

DSPy signature / typed prediction 추상화와 연결짓는 시각도 많았음:
"비싼 LLM 호출이 여러 개의 작고 태스크 특화된 AI 함수로 컴파일되는" 스택.
