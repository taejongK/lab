# 01. Jev 개요

출시: 2026-09-15 / TypeSafe AI / 창업자 Diego Almeida (前 OpenAI, ChatGPT·RLHF 참여)

## 핵심 주장

TypeSafe의 문제 제기는 이거다:

> "Models have been superhuman at chat for years, so where is all the automation?"

채팅은 이미 초인간 수준인데 왜 자동화는 안 늘었나 — 답은 "LLM이 사람을 향해 최적화됐기
때문"이라는 것. 그래서 **사람이 아니라 코드가 소비하는 모델**을 만들었다는 게 Jev.

## 포지셔닝

| | 하는 일 |
|---|---|
| 코드 | 계산한다 (calculate) |
| **Jev** | **판단한다 (judge)** |
| Reasoning LLM | 추론하고 생성한다 (reason & generate) |

멘탈 모델: **"전문가가 5초 안에 리서치 없이 내릴 수 있는 판단"을 머신 스케일로**.
설명이나 추론 체인이 필요한 판단은 Jev의 영역이 아님.

## 입출력

```
입력:  state (텍스트/구조화된 프로그램 상태) + 타입이 정의된 질문들
출력:  타입 안전한 값 + 전체 확률분포 + confidence (0~1)
```

텍스트를 한 글자도 생성하지 않는다. 이메일도, 코드도, 요약도 못 씀.

## 적합성 판단 (6문항 체크)

1. 콘텐츠 생성이 아니라 의사결정인가?
2. 답의 공간이 미리 정의되는가?
3. 단일한 초점의 판단인가?
4. 필요한 맥락이 전부 state 안에 들어가는가?
5. 사람 전문가가 빠르게 판단 가능한가?
6. 결과를 소프트웨어가 직접 소비하는가?

→ 5~6개 yes면 좋은 후보 / 3~4개면 쪼개라 / 0~2개면 도구가 틀렸다.

## 주요 유스케이스

- **분류**: 티켓 카테고리, 인텐트
- **탐지**: 정책 위반, jailbreak, 가드레일
- **스코어링**: 심각도, 관련성, 품질
- **라우팅**: 워크플로 분기 (+ confidence gate)
- **검색/리랭킹**: RAG 후보 필터링, 재정렬
- **LLM-as-judge 대체**: eval 채점기
- **map-reduce**: 대용량 데이터에 좁은 판단 대량 적용
- **실시간**: 70~500ms라 게임 루프 안에서도 동작 (Doom 데모)

## 권장 아키텍처

```
Application State
    ↓
결정론적 코드 (규칙/계산)
    ↓
Jev (의미적 판단)
    ↓
확률분포 + 타입 값
    ↓
결정론적 코드 (분기)
   ↙   ↓   ↘
Action  Review  Reasoning Model
```

제어 흐름은 코드가 소유하고, Jev는 일반 로직으로 안 되는 좁은 의미 판단만 공급.
