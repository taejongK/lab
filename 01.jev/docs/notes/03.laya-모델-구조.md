## 한 줄 요약

**Laya = 양방향 인코더(ModernBERT)에 "선택지마다 빈칸 하나씩 붙이고, 그 빈칸에 점수를 매기는" 작은 머리를 단 모델이다.**
글을 생성하지 않는다. 선택지 수만큼 점수를 내고, softmax로 확률로 바꿔서 끝난다.

---

## 1단계 — 중학생 버전

### 객관식 시험을 보는 학생

Laya가 하는 일은 객관식 문제를 푸는 것과 똑같다.

```
문제:  이 고객 문의는 어느 부서로 보내야 하나?
선택지: ① 결제   ② 기술지원   ③ 영업
지문:  "카드에서 두 번 결제됐어요. 빨리 고쳐 주세요."
```

보통 챗봇(GPT 같은 모델)은 이 문제를 **답안을 글로 써서** 푼다.
"이 문의는 결제 관련이므로 ①번입니다…"처럼 한 글자씩 쓰기 때문에 느리고, 가끔 엉뚱한 답을 쓰기도 한다.

Laya는 다르다. **글을 쓰지 않고 각 선택지 옆에 점수만 적는다.**

```
① 결제      ← 9점
② 기술지원  ← 1점
③ 영업      ← 0점
```

그리고 점수를 "전체 합이 100%"가 되도록 바꾼다. → ① 85%, ② 12%, ③ 3%.
답은 가장 높은 ①번이고, **85%라는 숫자가 "얼마나 자신 있는지"** 가 된다.

### 빈칸 표시 [MASK]

Laya는 문제지를 받으면 각 선택지 앞에 **빈칸 표시**를 하나씩 붙인다.

```
[문제] 어느 부서로? [빈칸]결제 [빈칸]기술지원 [빈칸]영업 [지문] 카드에서 두 번…
```

그리고 문제지 **전체를 한꺼번에** 읽는다. 앞에서 뒤로 한 글자씩 읽는 게 아니라, 모든 단어가 서로를 동시에 쳐다본다.
그러면 각 빈칸에는 "이 선택지가 이 지문·이 문제와 얼마나 잘 맞는지"에 대한 정보가 모인다.
마지막으로 작은 **채점기**가 빈칸마다 점수 하나를 매긴다.

### 왜 빠른가

- 답을 한 글자씩 쓰지 않는다. **한 번 읽고 끝**이다.
- 읽는 모델 자체도 작다. GPT류 대형 모델의 수백분의 일 크기(약 4억 개 숫자)라서 T4 같은 보급형 GPU에서 수십 ms면 끝난다.

### 세 가지 문제 유형

| 유형 | 예 | Laya가 하는 일 |
|---|---|---|
| **choice** | 어느 부서? | 선택지마다 빈칸, 가장 높은 것 선택 |
| **noul** (예/아니오) | 긴급한가? | "아니오", "예" 두 선택지로 바꿔서 똑같이 푼다 |
| **score** (점수) | 얼마나 화났나? (0~2단계) | "0단계", "1단계", "2단계"를 선택지로 바꿔 풀고, 확률로 평균을 낸다 (예: 1.4단계) |

즉 **세 유형 모두 "선택지 중 하나 고르기"로 바꿔서 푼다.** 이게 Laya 설계의 핵심이다.

## 2단계 — 고등학생/입문자 버전

### 부품 다섯 개

```
          입력 문장 (질문 + [MASK]선택지들 + 지문)
                         │
          ┌──────────────▼──────────────┐
  ①       │  인코더: ModernBERT-large    │  28층, 양방향. "읽는 눈"
          └──────────────┬──────────────┘
                         │  모든 토큰의 벡터 (길이 L × 1024)
  ②          + 질문 유형 표시 (choice / score / noul)
                         │
          ┌──────────────▼──────────────┐
  ③       │  결정 헤드: 트랜스포머 2층   │  처음부터 새로 학습한 부분
          └──────────────┬──────────────┘
                         │  [MASK] 위치의 벡터만 뽑음 (선택지 k개 × 1024)
          ┌──────────────▼──────────────┐
  ④       │  채점기: 작은 MLP → 점수 1개 │  선택지마다 같은 채점기
          └──────────────┬──────────────┘
                         │  softmax → 확률분포
                         ▼
                   답 + 확률 + confidence

  ⑤  행동 헤드(act head): "자동 처리 / 사람에게 넘김" 2지선다 — 현재는 쓸모없음 (§3.7)
```

| 부품 | 하는 일 | 크기 |
|---|---|---|
| ① 인코더 | 문장 전체를 양방향으로 읽어 토큰마다 의미 벡터를 만든다 | 약 395M (사전학습된 것을 가져와 미세조정) |
| ② 유형 임베딩 | 지금이 choice/score/noul 중 무엇인지 모든 토큰에 더해 준다 | 3 × 1024 |
| ③ 결정 헤드 | 인코더 위에서 한 번 더 문맥을 섞는다 (2층) | 약 25M (새로 학습) |
| ④ 채점기 | 각 [MASK] 벡터 → 점수 1개 | 약 1M |
| ⑤ 행동 헤드 | 확신도 특징 → act/escalate | 약 0.3M |

합계가 약 421M으로, README의 "ModernBERT-large 395M + 헤드"와 맞는다 (계산은 §3.3).

### GPT류와 무엇이 다른가

| | GPT류 (디코더) | Laya (인코더) |
|---|---|---|
| 읽는 방향 | 왼쪽 → 오른쪽 (앞만 봄) | **양방향** (모든 토큰이 서로를 봄) |
| 답 내는 법 | 다음 토큰을 하나씩 생성 | **[MASK] 위치마다 점수 1개** |
| 선택지 표현 | 어휘 사전의 토큰 행 (`" billing"`) | 선택지 텍스트 전체가 입력 안에 들어감 |
| 학습 없이 바로 쓰기 | 가능 (zero-shot) | **거의 불가** — 헤드가 학습돼야 함 |

## 3단계 — 정석적인 설명

### 3.1 입력 시퀀스 구성

질문 하나당 시퀀스 하나를 만든다 (`C:build_sequence`, `C:build_head`).

```
[CLS] "<type> question: <instructions>" [SEP]
      [MASK] opt_0  [MASK] opt_1  …  [MASK] opt_{k-1} [SEP]
      <state> [SEP]
```

- 선택지 텍스트는 유형별로 렌더링된다 (`C:render_options`).
  - choice: `"label"` 또는 설명이 있으면 `"label: 설명"`
  - score: `"level i: 설명"`
  - noul: `["false: no, the statement does not hold", "true: yes, the statement holds"]` (라벨과 설명은 바꿀 수 있음)
- **토큰 예산**
  - 선택지 하나는 최대 48토큰.
  - 질문과 선택지를 합친 머리 부분은 `head_max_len=192`.
  - 전체 시퀀스는 `max_len=512` (영어 체크포인트 기준. 설정은 [`rl_agent_config.json`](https://huggingface.co/convaiinnovations/laya/blob/main/rl_agent_config.json)).
  - 선택지가 많아 예산을 넘으면 선택지당 토큰을 균등하게 깎는다. 최소 4토큰.
  - state는 남는 자리에 들어가고, 넘치면 **조용히 잘린다**.
- `markers`: 각 `[MASK]`의 위치 인덱스. 모델 출력에서 이 위치만 꺼내 쓴다.

### 3.2 순전파 (`C:DecisionModel.forward`, L609)

입력 길이를 $L$, 은닉 차원을 $d=1024$, 선택지 수를 $k$라 하자.

$$
\begin{aligned}
H &= \mathrm{Enc}_\theta(x) \in \mathbb{R}^{L\times d} && \text{(ModernBERT, 양방향)}\\
H' &= H + \mathbf{1}\,e_{\text{type}}^\top && \text{(유형 임베딩을 모든 위치에 더함)}\\
H'' &= \mathrm{TrEnc}^{(2)}_\phi(H') && \text{(pre-norm 트랜스포머 2층, 헤드 } d/64=16\text{개, FFN } 4d)\\
m_j &= H''[\text{marker}_j] \in \mathbb{R}^{d}, \quad j=1..k && \text{(각 [MASK] 위치를 gather)}\\
z_j &= w_2^\top\,\mathrm{GELU}(W_1\,\mathrm{LN}(m_j)+b_1)+b_2 && \text{(공유 스칼라 채점기)}\\
p &= \mathrm{softmax}(z / T_{\text{bucket}}) && \text{(추론 시 temperature 적용)}
\end{aligned}
$$

핵심은 $z_j$를 만드는 **채점기가 모든 선택지에 공유되는 스칼라 함수**라는 점이다.
선택지 수 $k$가 파라미터 모양에 들어가지 않는다. 그래서 학습 때 못 본 선택지 집합과 개수에도 그대로 적용할 수 있다.
BERT 분류기처럼 출력층이 $k\times d$ 행렬이면 레이블 집합이 바뀔 때마다 재학습해야 하는데, Laya는 그렇지 않다.
레거시 06 문서가 말한 "세 번째 길(후보별 경로 + 공유 스칼라 head)"의 인코더판이다.

차이가 하나 있다. NanoJev처럼 후보마다 백본을 따로 태우지 않는다. **모든 선택지를 한 시퀀스에 넣고 한 번에 인코딩**한다.
그래서 선택지들이 attention으로 **서로를 본다.** "이 중에서 고른다"는 비교가 인코더 안에서 일어난다.

### 3.3 파라미터 수

| 부분 | 계산 | 값 |
|---|---|---|
| 인코더 | ModernBERT-large (28층, $d$=1024, FFN 2624, vocab 50,368) | ≈ 395M |
| 결정 헤드 2층 | 층당 attention $4d^2$ + FFN $2\cdot d\cdot 4d$ ≈ 12.6M | ≈ 25.2M |
| 채점기 | $d^2 + d + d$ | ≈ 1.05M |
| 행동 헤드 | $(d+4)\cdot 256 + 256\cdot 2$ | ≈ 0.26M |
| 유형 임베딩 | $3d$ | 3K |
| **합계** | | **≈ 421M** |

인코더 설정은 [`encoder/config.json`](https://huggingface.co/convaiinnovations/laya/blob/main/encoder/config.json) 기준이다. 3층마다 global attention, 나머지는 128토큰 local window를 쓰고, RoPE에 위치 8,192까지 지원한다.
ModernBERT의 원래 설계는 [Warner et al. 2024](https://arxiv.org/abs/2412.13663)를 참고.

### 3.4 질문이 여러 개일 때 — "single forward pass"의 실제 의미

질문 $Q$개에 state 하나가 들어오면 **시퀀스 $Q$개**를 만든다.
state 토큰화는 한 번만 하지만(`state_ids` 재사용, `A` L1149), 각 시퀀스에 **state가 통째로 복사**된다.
이 $Q$개 행을 배치로 묶어 forward를 **한 번** 호출한다.

코드 주석이 이유를 직접 설명한다 (`C` L425-427).

> "because the encoder is bidirectional the head cannot be computed once and reused — its representations depend on the state it is paired with."

양방향 인코더에서는 질문 토큰의 표현이 뒤에 오는 state에 의존하고, state의 표현도 질문에 의존한다.
그래서 디코더처럼 "state를 한 번 prefill하고 KV 캐시를 질문마다 재사용"하는 게 **구조적으로 불가능하다.**
README의 "single forward pass"는 **호출 횟수가 1번**이라는 뜻이다. **연산량은 질문 수에 비례**한다.

> 대조: 디코더 기반 구현(SemIf, rizzo-flow, decider 등)은 state를 한 번만 prefill하고 질문을 분기할 수 있다.
> 긴 state + 많은 질문이면 오히려 그쪽이 유리할 수 있다.

### 3.5 출력 디코딩 (`A:_decode_answers`, L1330)

| 유형 | 반환값 | 계산 |
|---|---|---|
| choice | `choice`, `probabilities` | $\arg\max_j p_j$ |
| score | `score` (기대 레벨) | $\sum_{i=0}^{k-1} i\cdot p_i$ |
| noul | `noul` = P(true) | $p_1$ |

confidence는 **두 종류**다. 이 구분이 중요하다.

- `answer_confidence` $= \max_j p_j$: temperature가 맞추는 대상이고 ECE를 재는 값. **게이팅에는 이걸 써야 한다.**
- `confidence` $= 1 - H(p)/\log k$: 정규화 엔트로피. 분포가 얼마나 몰려 있는지만 나타내고 **calibration이 보장되지 않는다** (`C:confidence_from_probs` docstring).

### 3.6 Temperature — 버킷별 사후 보정

추론 때 로짓을 $T$로 나눈다. $T$는 (유형, 선택지 수) 버킷마다 따로 있다 (`C:temp_bucket`).
아래는 영어 체크포인트 설정값이다.

| 버킷 | T |
|---|---|
| choice:2 | 1.91 |
| choice:3-5 | 1.76 |
| choice:6-10 | 1.00 |
| choice:11+ | **0.10** → 실행 시 하한 0.5로 클램프 |
| score:3-5 | 1.25 |
| noul:2 | 1.98 |

- 대부분 $T>1$이다. 즉 **학습된 모델이 과신(over-confident)** 하고, 사후에 분포를 평평하게 만들어 고친다.
- `choice:11+`의 0.10은 오히려 10배로 날카롭게 만드는 값이다. 코드 주석 스스로 "0.24짜리 확률을 0.99로 발표하게 된다"며 이 값을 거부한다 (`C` L820-843, issue #394).
- 정리하면 **calibration의 상당 부분은 학습이 아니라 이 버킷별 temperature가 하고 있다.**

### 3.7 행동 헤드 (act head)

입력은 `[CLS]` 벡터에 확신도 특징 4개(top1, top1−top2, 정규화 엔트로피, $k/255$)를 붙인 것이다.
출력은 "act / escalate" 2지선다다 (`act_costs: {escalate: 0.5}`).
Jev식 "자동 처리할지 사람에게 넘길지"를 모델이 직접 판단하게 하려는 의도다.

하지만 README가 스스로 인정한다 (L1635).
> "`action.act_probability` carries no usable signal yet (#185). It reads 1.0 for almost every input, and its raw logits run against correctness (AUROC 0.30)."

현재 공개된 학습 루프(`T:train_model`)도 이 헤드에는 손실을 걸지 않는다. **장식품**으로 보면 된다.

### 3.8 학습 목적함수 — Laya의 "RLCD"

`T:rlcd_loss` (L499)가 전부다.

1. 현재 로짓 $z$를 고정(detach)하고, 가우시안 잡음 $\epsilon^{(s)}\sim\mathcal{N}(0,\sigma^2 I)$을 $S=4$번 더한다. 잡음은 선택지 위에서 평균 0이 되도록 사영한다.
2. 각 샘플 분포 $q^{(s)}=\mathrm{softmax}(z+\epsilon^{(s)})$에 **proper scoring rule 보상**을 준다 (`C:proper_reward`).

$$
R(q, y) = \underbrace{\sum_j y_j \log q_j}_{\text{log score}} + 0.75\,\underbrace{\frac{\langle y, q\rangle}{\lVert q\rVert}}_{\text{spherical}} - \mathbb{1}[\text{score}]\cdot\underbrace{\frac{\sum_i (F_q(i)-F_y(i))^2}{k-1}}_{\text{RPS}}
$$

3. 그룹 안에서 정규화한 advantage $A^{(s)} = (R^{(s)}-\bar R)/\mathrm{std}$로 가우시안 정책의 로그밀도에 가중치를 준다. 여기에 soft cross-entropy를 더한다.

$$
\mathcal{L} = -\frac{1}{S}\sum_s A^{(s)}\cdot\Big(-\frac{\lVert z+\epsilon^{(s)}-z_\theta\rVert^2}{2\sigma^2}\Big) \;+\; \mathrm{CE}(y,\ \mathrm{softmax}(z_\theta))
$$

$\sigma$는 0.4에서 0.1로 epoch마다 선형 감소한다.

**이걸 어떻게 읽어야 하나**
- 텍스트를 샘플링하는 RL이 아니다. **로짓 공간에서 가우시안 정책을 쓰는 REINFORCE**([Williams 1992](https://doi.org/10.1007/BF00992696))다. 그룹 평균을 baseline으로 쓰는 점이 [GRPO](https://arxiv.org/abs/2402.03300)와 닮았을 뿐이다.
- log score, spherical score, RPS는 모두 **strictly proper scoring rule**이다 ([Gneiting & Raftery 2007](https://doi.org/10.1198/016214506000001437)). 이걸 최대화하면 이론적으로 참 분포에 수렴한다.
  그런데 **soft CE 자체가 이미 log score**라서, 같은 목표를 한 번 더 거는 셈이다.
- 실제로 `train.py` docstring이 이렇게 적고 있다.
  > "`loss="soft-ce"` trains on the soft cross-entropy alone; #741 measured no gain from the extra term on the typed-decisions split."

  RLCD 항을 빼도 차이가 없었다는 저자 측 측정이다. 이슈 원문은 확인하지 않았다.
- 학습된 손실은 **마스크를 통과한 결정 분포 위에** 걸려 있다. 레거시 06 문서 §6이 예측한 "RLCD가 실재한다면 이런 모양"과 형태는 같다.
  하지만 그 효과는 사실상 **일반적인 지도학습(CE)과 구분되지 않는다**는 게 Laya 저자 측 결과다.

### 3.9 구조에서 나오는 한계

| 한계 | 원인 (코드) | 저자 측 수치·서술 |

## 4. System One 관점에서 정리

Laya를 통해 보면 "System One 모델"은 다음 네 가지 설계 결정의 묶음이다.

1. **출력 공간을 입력으로 옮긴다.** 선택지를 생성 대상이 아니라 입력 텍스트로 넣고, 각 선택지 위치에서 점수 하나를 읽는다.
   → 스키마 밖 출력이 원리적으로 불가능하다 (타입 안전).
2. **모든 유형을 "k지선다"로 환원한다.** noul = 2지선다, score = 순서 있는 k지선다(기대값으로 읽음).
   → 하나의 채점기로 세 프리미티브를 처리한다.
3. **채점기를 선택지 수와 무관한 공유 함수로 만든다.** $z_j = f(m_j)$.
   → 레이블 집합이 바뀌어도 재학습이 필요 없다. 단, 학습은 반드시 필요하다.
4. **확률을 결정 분포 위에서 직접 학습하고, 사후 temperature로 보정한다.**
   → "calibrated confidence"의 실체. Laya에서는 학습 항(RLCD)보다 사후 보정의 비중이 크다.

레거시 06 문서의 LM head readout(디코더 + 선택지 토큰 logit 읽기)과 비교하면 이렇다.

| | LM head readout | Laya |
|---|---|---|
| 선택지 표현 | 어휘 사전 행 (프리트레인됨) | 입력 안의 `[MASK]`+텍스트 (문맥화됨) |
| 학습 필요 | 없음 (zero-shot) | **필수** |
| 첫 토큰 충돌 | 있음 | 없음 (대신 토큰 예산 문제) |
| 선택지 간 비교 | 없음 (각 토큰 logit 독립) | 인코더 안에서 attention으로 비교 |
| state 재사용 | KV 캐시로 가능 | 불가 (양방향) |
| 확률이 학습된 층위 | 텍스트 분포 | **결정 분포** |

**다음에 볼 것**
- 학습 데이터 구성: 저자는 typed-decisions의 train split으로 파인튜닝했다. 이게 Jev를 "이겼다"는 수치와 직결된다.
- `parallel_layout`로 학습하면 순서 편향이 실제로 사라지는지.
- soft-CE만 쓴 학습과 RLCD 학습의 ECE 차이를 직접 재현 (#741).
